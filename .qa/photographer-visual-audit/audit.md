# 摄影师端移动 H5 视觉层级审计

## 审计范围

- 任务页：进行中状态、已完成状态
- 相册页：无照片空状态
- 视口：390 × 844
- 目标：在不改变路由、跳转和业务操作的前提下，重建摄影师端视觉层级

## 总体判断

当前页面的可用性基础尚可，但视觉层级仍是“功能平铺”。头图、加入入口、可加入房间、已加入任务和筛选标签都在竞争注意力，摄影师最重要的“当前任务”没有成为页面主角。相册页则存在标题重复和空状态占比过大的问题。

1. `01-task-active.png`：进行中任务。健康度：需重构。
2. `02-task-completed.png`：已完成任务。健康度：需重构。
3. `03-album-empty.png`：相册空状态。健康度：需优化。

## 关键问题

### P0 结构问题

1. 任务页的顺序是头图、加入入口、可加入房间、任务标签、已加入任务。用户自己的任务反而排在第三层。
2. 可加入房间与已加入任务使用相近的白色横向卡片，难以快速区分“发现”与“我的任务”。
3. 进行中、直播中、进行中标签与任务状态重复出现，绿色承担了过多含义。
4. “进行中 / 已完成”标签只控制下方任务，但视觉上像在控制整个页面；切到已完成后，上方仍显示直播房间，层级语义冲突。

### P1 视觉问题

1. 深绿色头图占据较大高度，却只承载问候和标题，没有人物、当前任务数量或辅助说明，信息效率偏低。
2. 当前已加入任务只是一张普通小卡，没有成为摄影师工作的主入口。
3. 页面下半部分出现大面积空白，内容像停在上半屏，底栏与主体割裂。
4. 相册页“我的相册”和“已上传照片”表达重复，标题系统不统一。
5. 相册空状态卡面积远大于信息量，且“去上传照片”实际先回到任务页，动作预期不够准确。

### P2 可读性与无障碍风险

1. 次级浅绿色文字和空状态图标对比度偏低。
2. 在线人数、房间号和状态徽标的字号偏小，户外使用时可读性不足。
3. 房间名依赖省略号，已完成任务名称在可见层面信息不完整。
4. 截图只能确认视觉状态，键盘焦点、读屏顺序和缩放 200% 仍需实施后测试。

## 修复方案

### 任务页

1. 将顶部重构为 140-160px 的摄影师工作台头图：左侧问候、标题、辅助说明，右侧使用现有摄影师人物素材。
2. 将“我的任务”提升到第一业务层，紧接头图展示；进行中与已完成标签归属于该区块。
3. 已加入的进行中任务使用主任务卡：更大封面、清晰状态、房间号与主操作，成为页面唯一强卡片。
4. 将“加入新房间”改为第二层独立入口，保持原点击逻辑。
5. 将“正在进行的房间”降为发现区，使用弱边框、较小卡片或单条预览，与已加入任务形成明显区分。
6. 已完成任务使用紧凑列表，突出“字幕/纪要”，弱化直播相关元素。

### 相册页

1. 标题统一为“我的相册”，说明保留“管理你在各房间上传的照片”，移除重复眉题。
2. 空状态缩为 200-220px，并靠近标题区域，不再占据半屏。
3. 主按钮文案改为“去任务页上传”，明确真实去向，路由保持不变。
4. 有照片时保留房间筛选与三列网格，但提高筛选与照片网格之间的层级分隔。

### 统一规格

- 页面左右边距：20px，320px 视口降为 16px。
- 一级标题：28px；区块标题：18px；卡片标题：16px；正文：14px；辅助信息不低于 12px。
- 绿色只用于主操作、选中状态和真实直播状态。
- 任务主卡圆角 20px，普通列表卡 16px，控件圆角 12-14px。
- 底部内容必须预留安全区，320px 与 390px 均不得横向溢出。

## 实施顺序

1. P0：重排任务页信息架构，区分“我的任务”和“发现房间”。
2. P1：重做头图、主任务卡、相册标题与空状态。
3. P2：统一字号、对比度、窄屏换行与触控反馈。
4. 复验：320 × 700、390 × 844，覆盖进行中、已完成、加载、失败、空状态和相册有图状态。
