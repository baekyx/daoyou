# 摄影师端功能、持久化与 UI 审查

审查日期：2026-07-30  
本地项目：`app-d04hti6zlz42-4`

## 总体结论

摄影师端的基础闭环已经形成：房间号查询、历史任务、照片相册、个人资料、上传质量偏好、协议查看和意见反馈均有真实实现。审查中已读取到持久化的已结束任务和两张照片，并实际提交了一条标记为“摄影师端功能验收测试”的反馈，提交成功。

当前还不能认定“每个功能均完整可用”。主要原因是直入房间迁移编号冲突、部分入口只有界面没有业务执行、列表存在静默截断，以及当前账号没有进行中的摄影任务，无法在不改变业务数据的情况下完成一次新的照片上传。

## 高优先级问题

1. `00050_a3_03_02b_revoke_internal_fn_anon.sql` 与 `00050_photographer_direct_join.sql` 使用同一迁移版本号，摄影师直入 RPC 可能无法稳定部署。
2. “扫码 / 输入房间号加入”没有扫码逻辑，当前只有手动输入房间号。
3. “仅 Wi-Fi 上传”只保存开关，上传页面完全没有读取或执行该设置。
4. 摄影师任务页没有“当前可加入房间”列表；已有 `fetchActiveRooms()` 可复用，但服务端查询应补上 `discoverable = true`。
5. 相册最多读取 10 个房间、每房最多 200 张照片，且错误被当成空数据，用户可能误以为照片丢失。
6. 身份与账号页直接展示完整手机号，与“我的”页的脱敏规则不一致。
7. 删除照片要求摄影师仍保有有效 membership；退出或被撤销后可能无法删除本人照片。数据库记录删除后若 Storage 删除失败，公开文件仍可能通过原链接访问。
8. `updateProfile()` 未验证实际更新行数，极端情况下可能“0 行更新但提示成功”。
9. 上传允许选择 HEIC/HEIF，但多数浏览器不能通过 Canvas 解码压缩，高清/标准模式可能失败。

## UI 与可访问性问题

1. 图标语义不统一：任务使用景点建筑、存储使用相册、隐私使用建筑，角色又混用 Emoji。
2. 同一页面同时出现 Lucide 图标、Emoji、文字箭头 `›` 和 CSS 箭头，视觉语言不一致。
3. 密码的 6 个输入框没有可访问名称；身份页返回按钮、协议弹窗关闭按钮也缺少明确标签。
4. 次要文字大量使用 10–12px 浅绿色/浅灰色，弱光环境和户外场景下可读性不足。
5. “提交申请”与当前“密码正确即直接加入”的业务不一致，应改为“验证并加入”。
6. 相册删除按钮虽然具备 44px 点击区域，但覆盖在图片上，视觉识别度较低，且缺少照片时间、数量和上传状态。

## 最小改动图标方案

继续使用项目已有的 Lucide，不引入新依赖、不改页面布局。

### 统一规则

- 普通描边：`strokeWidth 1.8`
- 选中/主要状态：`strokeWidth 2.2`
- 底部导航：22px
- 菜单图标：18px，放入 36×36、10px 圆角的浅色容器
- 行内操作：16px
- 空状态：36px
- 仅危险操作使用红色；其他图标只使用品牌绿、深墨色和中性灰
- 删除 Emoji、文字箭头和手写 SVG，统一用图标库组件

## “当前进行中房间”最小改动方案

在任务页“输入房间号加入”下方、“我的任务”标签上方增加一个紧凑列表：

- 标题：`正在进行的房间`
- 每项显示：封面、房间名、导游头像/昵称、`直播中` 状态、在线人数
- 主按钮：`输入密码加入`
- 点击后直接复用现有密码验证页，不改变加入流程
- 默认显示 3 条，可进入“查看全部”
- 只显示 `status = live` 且 `discoverable = true` 的房间
- 每 15 秒刷新一次，页面重新可见时立即刷新
- 不需要新增第三方 API 或新的密钥
