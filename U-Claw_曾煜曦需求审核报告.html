KEEP / 01

保留 V2 Windows 样品方向

官方支持原生 Windows，便携 Node + 定向 state/workspace 路径具备验证价值。

CHANGE / 02

从“整盘克隆”改为“净化模板物化”

只克隆预置配置与知识资产，不克隆 auth、session、测试记录和用户密钥。

CHANGE / 03

密钥默认不随盘保存

安全默认应为每次输入；若产品坚持保存，增加用户口令加密且口令不得落盘。

REJECT / 04

不改 OpenClaw 核心为双数据库

当前官方状态由 workspace、agentDir、sessions、SQLite 等组成；核心改造超出 5 周样品边界。

REJECT / 05

不承诺“盘外绝对不可访问”

workspace 不是硬沙箱；无 Docker/WSL2 条件下，只能做工具最小化与“默认不访问”的降级承诺。

GATE / 06

第 3 周 PoC 决定 V2 / V1

干净机、盘符变化、普通权限、杀软、拔插恢复五类证据必须留档。

矛盾、违背与不清楚

以下内容必须在主报告和实施方案中统一，否则同一团队会按不同版本开发和验收。

类型冲突两端判断应如何改写
安全冲突“Key 随盘保留” ↔ “不预置 Token / 密钥不好保存、容易泄露”便携与机密性不能无成本同时满足。默认不保存；可选口令加密。把“Token 随盘”统一改为“配置与会话随盘，密钥按用户选择保存”。
隔离冲突“盘外文件碰不到” ↔ “原生 Windows、无 Docker/WSL2”缺少可证明的硬隔离机制。改为工具策略与默认行为承诺；若必须硬隔离，另立 Docker/VM/专用主机路线。
架构冲突主方案 `data/` 整体覆盖 ↔ 分析报告 system.db/user.db ↔ 官方 per-agent 多目录三套存储模型互相不兼容。以锁定版本的官方目录为真相源，输出一份路径/数据分级 manifest；取消核心双库改造。
可靠性冲突“断电拔盘后可恢复” ↔ “内存驻留 5 分钟刷盘”内存写回会扩大数据丢失窗口。用户状态即时事务落盘；只缓存可重建索引/只读块，恢复口径限定为最近一致状态。
入口冲突实施方案用 `.bat` ↔ 分析报告和群聊主张 Rust/C++ launcherPoC 入口与交付入口被混为一谈。明确 `.bat = 第 2-3 周内部 PoC`，`launcher.exe = 第 4-6 周样品交付`。
平台冲突V2 Windows-only ↔ 文件系统又为二期 Mac 牺牲 ↔ V3 不承诺二期目标干扰一期决策。V2 选择 NTFS；V3 重新评估 Mac 镜像/分区，不保证共享运行数据库。
体验冲突“填 Key 后开始对话 ≤3 步” ↔ “保存后重启生效”用户步骤定义不一致。“保存并启动”由 launcher 自动重启服务，不把重启暴露为用户操作。
版本违背方案 B 写“Node 18+ 内置 fetch” ↔ 当前 OpenClaw 官方 Node 最低版本更高过时前提会导致错误打包。不写泛化 Node 18；锁定经过验证的 Node 精确版本并记录 hash。
术语不清API token / API Key / Token 随盘混用群聊已指出表达问题，不同 Provider 的 credential 也不等价。统一用“模型服务商 API Key/凭据”；Gateway token 单独称“本地网关访问令牌”。
范围不清22 项基本功能、三项增强至少两项、Office 解析器、最小可写目录缺清单、选型、验收步骤和负责人。全部进入需求基线表；没有 ID 和验收步骤的条目不得进入“完成度 100%”。
成本违背5 周二人执行 ↔ 新增 launcher、安全设置页、6 Agent/RAG、三机/杀软/恢复测试现范围大于现有人力估算。要么增补 1 名前端/Windows 工程人力，要么先交 2 Agent + 手动配置的 V2a，再扩 6 Agent。
宣传风险“任意电脑即插即用”心智 ↔ 指定版本 Windows + 普通权限/杀软/硬件差异主报告的谨慎口径正确，必须压过群内口语宣传。统一为“在已验证的 Windows 11 版本与设备条件下便携运行；兼容范围见清单”。

密钥泄露

判断：原方案不可接受。

控制：默认不保存；可选口令加密；日志/崩溃报告必须脱敏；丢盘应有撤销与轮换指引。

宿主机文件越界

判断：“绝对隔离”不可接受为宣传。

控制：最小工具、workspaceOnly、禁 exec/elevated/browser、loopback + auth；PoC 做越界用例。

母盘克隆隐私污染

判断：整目录直接克隆不可接受。

控制：allowlist manifest、secrets scan、净化模板、首启生成唯一标识；克隆后做差异扫描。

杀软误报与启动失败

判断：样品期可接受，量产前不可忽略。

控制：原生 launcher、代码签名预算、主流 Defender/火绒/360 实测、可读错误与离线日志。

拔盘/断电数据库损坏

判断：只能接受“可恢复”，不能接受“零丢失”。

控制：显式安全关闭、写入中提示、事务/WAL、轮转备份、启动完整性检查、恢复演练。

OpenClaw 快速变更

判断：锁版本后可接受。

控制：精确版本与 hash、SBOM、禁 latest、离线依赖、单独安全补丁通道与回滚包。

专业 Agent 内容责任

判断：治理后可接受。

控制：来源、地域、版本日期、免责声明、拒答边界、内容更新人；健康类不诊断不处方。

排期与人工低估

判断：当前数字不能写死。

控制：PoC 后重估；V2a 优先 2 Agent + launcher + 安全配置，6 Agent/RAG 扩展为下一里程碑。
