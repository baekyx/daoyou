# 任务二：技术人员所需资源与服务清单

> 目标：只提供完成学生版 Windows SSD MVP 真正需要的资源，避免采购服务器、GPU、域名和复杂平台

## 1. 开始开发前必须提供

| 资源/服务 | 数量 | 谁提供 | 用途 |
|---|---:|---|---|
| Windows 11 x64 开发电脑 | 1 台 | 团队成员 | 拉取代码、安装依赖、构建 Electron 应用 |
| Windows 10/11 干净测试电脑 | 1 台 | 团队借用 | 验证没有 Node/Git/Docker 时能否启动 |
| 移动 SSD | 1-2 块 | 项目组采购 | 1 块开发测试，条件允许时另备 1 块验收 |
| GitHub 账号和团队仓库 | 1 个 | 项目负责人 | 保存 fork、提交记录和 GPL 对应源代码 |
| 测试模型 API Key | 1-2 个 | 项目负责人 | 建议一个低成本主测试 Key、一个兼容性 Key |
| 可访问 GitHub/npm 的网络 | 1 条 | 学校或个人网络 | 下载源码、Node、npm 依赖和 OpenClaw 包 |
| 产品名称和启动文案 | 1 套 | 产品负责人 | 替换应用名称、欢迎页和说明文件 |

## 2. 推荐但不是必须

| 资源/服务 | 用途 | 没有时的替代方案 |
|---|---|---|
| 第 2 台不同品牌 Windows 电脑 | 检查兼容性和安全软件拦截 | 借用同学电脑测试半天 |
| Windows 非管理员账户 | 检查是否会要求提权 | 在开发机新建本地普通账户 |
| USB-A、USB-C 转接头 | 验证不同接口 | 验收时只声明支持已测试接口 |
| 简单图标 | 应用和 SSD 根目录识别 | MVP 沿用临时图标并标注测试版 |
| 演示录屏工具 | 形成汇报材料 | 使用 Windows 自带截图/录屏 |

## 3. 明确不需要采购

本期不需要：

- 云服务器、VPS 或 Kubernetes。
- GPU、显卡服务器或本地大模型设备。
- 数据库、对象存储和云账号系统。
- 域名、备案、HTTPS 证书。
- 短信、邮件、支付或会员服务。
- Apple 开发者账号和 Mac 打包服务。
- Windows 代码签名证书。
- 自动更新服务器和崩溃分析平台。

Windows 代码签名对正式销售有价值，但学生样品可以先不购买。没有签名时，Windows 可能显示未知发布者或 SmartScreen 提示，应在已知问题中如实说明。

## 4. 技术人员需要的访问权限

### 4.1 GitHub

- 可以 fork 和 clone 目标仓库。
- 可以创建分支、提交代码和发布测试包。
- 仓库在分发 GPL 修改版时应保持公开，或至少保证购买者可以获得对应源码。
- 禁止把 API Key 提交到 GitHub。

### 4.2 模型 API

- 提供测试专用 Key，不使用个人主账号长期密钥。
- 设置较低消费上限或余额提醒。
- 验收结束后可以轮换或作废测试 Key。
- 交付盘中不得保留团队测试 Key。

### 4.3 测试电脑

- 允许运行未签名的学生测试程序。
- 允许查看任务管理器和应用日志。
- 不要求关闭学校或公司的安全策略；如果被策略禁止，应记录为环境限制，而不是强行绕过。

## 5. 建议的软件环境

开发电脑安装：

- Git。
- 与 OpenClaw 版本匹配的 Node.js。
- pnpm。
- Visual Studio Code 或其他编辑器。
- 项目依赖要求的 Windows 构建工具。

测试电脑不要预装 Node.js、Git、pnpm、Docker 或 WSL，以验证便携包确实包含运行所需内容。

## 6. 项目负责人必须提前确认的事项

技术人员开始前，负责人需要一次性确认：

1. 本阶段只做 Windows 10/11 x64。
2. 允许采用 GPL-3.0 开源项目并公开修改源码。
3. 用户自备 API Key，产品不附送模型额度。
4. MVP 不承诺完全离线和所有数据绝不上云。
5. MVP 可以使用原项目界面，不要求重新设计。
6. 不要求自动更新、消息渠道和本地模型。
7. 验收以 8 项流程测试为准，不临时增加功能。

如果第 2 项不能接受，应停止使用 `agentkernel/openclaw-desktop`，改走“官方 MIT OpenClaw + 自有简单启动器”的路线，工作量会增加约 3-5 个有效工作日。

## 7. 对技术人员的任务包

为了减少沟通成本，建议直接按任务包分配，而不是按模糊角色分工。

### 任务包 A：原项目跑通

- Fork 仓库。
- 在 Windows 开发机完成依赖安装和开发运行。
- 记录使用的 Node、pnpm、OpenClaw 和桌面壳版本。
- 输出“可继续/不可继续”结论。

预计：1 个有效工作日。

### 任务包 B：SSD 便携化

- 修改 Electron `userData` 路径。
- 修改 OpenClaw 状态、配置和工作区路径。
- 确保路径随盘符变化。
- 禁用系统服务、计划任务和自动更新。

预计：2-3 个有效工作日。

### 任务包 C：打包和恢复

- 生成 portable 包或可复制目录。
- 准备默认配置和工作区模板。
- 编写恢复出厂脚本。
- 加入许可证和版本说明。

预计：2 个有效工作日。

### 任务包 D：测试和交付

- 在至少 2 台电脑测试。
- 修复阻断启动的问题。
- 制作母盘和使用说明。
- 记录不能解决的兼容性问题。

预计：2-3 个有效工作日。

## 8. 支持与沟通规则

- 每天只同步一次：已完成、当前阻塞、下一步。
- 产品负责人不得在开发中途增加 macOS、本地模型或新界面。
- 遇到兼容性问题，先判断是否影响验收环境，不为所有电脑做无限适配。
- 所有测试 Key、用户数据和个人文件在制作母盘前必须清除。
- 每次可以演示的版本都打 Git 标签，并在 `VERSION.txt` 记录对应提交。

## 9. 最小启动条件清单

只有以下项目齐全后才开始计算开发周期：

- [ ] Windows 开发机可用
- [ ] 干净测试机已确定
- [ ] SSD 已到手
- [ ] GitHub 仓库已建立
- [ ] 测试 API Key 可用且有限额
- [ ] GPL 开源分发要求已确认
- [ ] 产品负责人确认 MVP 边界
- [ ] 验收日期和验收人员已确定
