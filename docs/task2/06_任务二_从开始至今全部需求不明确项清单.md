# 任务二：从开始至今全部需求不明确项清单

> 整理日期：2026-08-07  
> 信息来源：原始任务书、可行性报告 v1、沟通截图、当前 MVP 文档、USB 配置与预制 Agent 方案  
> 用途：在继续开发前统一口径，防止不同成员按不同产品理解执行

## 1. 状态说明

- **已澄清：** 当前已经形成可执行口径，除非负责人提出变更，不再讨论。
- **待确认：** 仍会影响工作量、交付或宣传，必须由负责人决定。
- **MVP 删除：** 技术上可能实现，但当前学生样品不做。
- **原文错误：** 原方案中的技术事实、路径或承诺不准确，不能直接进入需求。

12. 文件能力只验收 TXT/Markdown，还是必须包含 PDF？

14. 最终公司名称、Logo、电话、客服链接和二维码是什么？
15. 恢复出厂时是否同时清除 Token、会话和用户工作区？

## 21. 当前已经可以直接写死的口径

以下内容已经多次讨论，不建议再次变化：

- 普通 SSD 不负责计算，Windows 宿主电脑运行程序。
- 当前只做 Windows 10/11 x64。
- 不做本地大模型和完全离线模式。
- 用户自备 API Key，产品不附送密钥和模型额度。
- 不从零开发 OpenClaw、聊天界面和配置系统。
- 不做 macOS、Linux、Windows ARM。
- 不做自动更新、系统服务、计划任务和企业后台。
- 不新建 Token 写入接口，直接复用桌面项目现有向导。
- 不复制包含运行状态和密钥的数据库作为母盘。
- Agent 使用工作区模板和官方 CLI 创建。
- 不预置健康顾问。
- 不宣传“数据永不上云”“内置 GPT”“任意电脑都能用”。
- 技术团队以 1 名主力为核心。
- 目标周期是 7-10 个有效工作日、2-3 个自然周。
- 学生项目预算建议控制在 3,000-6,000 元。
- 第一批只做 3-10 套验证样品。

## 22. 建议的需求冻结方式

项目负责人只需对第 20 节的 20 个问题逐项回答。回答完成后，把结果写入 PRD 首页作为“冻结口径”，开发人员只按冻结后的内容执行。

任何不在冻结口径和 8 项 MVP 验收中的新增需求，都自动进入二期，不影响当前样品验收和补贴结算。
