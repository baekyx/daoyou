# USB 版 OpenClaw 配置与预制 Agent 方案：技术审核与复用清单

> 审核日期：2026-08-07  
> 审核对象：《USB版OpenClaw配置与预制Agent方案》7页 PDF  
> 审核基线：学生团队、Windows 10/11 x64、基于现有桌面项目改造、不从零开发

## 1. 审核结论

这份方案的产品方向基本正确，但技术细节不能直接作为开发说明执行。

综合判断：

- **产品思路可行：** 品牌信息、首次配置入口、预置 Agent、使用说明和空白母盘都可以实现。
- **约一半内容可直接吸收：** 不预置正式 Token、制作空白模板、正常关闭后复制、限制危险权限、提供离线使用说明。
- **关键实现方式需要重写：** 文档假定了若干未经确认的目录、数据库和 API；直接照抄可能无法运行。
- **学生 MVP 不需要新增 Token 配置页面：** 选定的 `agentkernel/openclaw-desktop` 已有 Provider 配置向导，应直接复用。
- **预置 Agent 不建议复制整个数据库：** 更稳妥的方式是准备干净的 Agent 工作区模板，并通过 OpenClaw 官方 CLI 首次初始化。

最终建议：

> 保留“品牌入口 + 现有配置向导 + 3 个轻量 Agent 模板 + 使用说明”的产品设计；删除自建 Token 写入接口、数据库整盘复制和未经验证的 Agent 导入 API。

## 2. 逐项可行性审核

| PDF 中的主张 | 可行性 | 审核意见 | MVP 处理 |
|---|---|---|---|
| 页面展示公司名称、客服和在线链接 | 可行 | 应修改实际 Electron/React 组件后重新构建，不应假设存在 `portable/app/web/index.html` | 做一个“技术支持”入口或关于页 |
| 在网页填写 Token 并保存到 SSD | 可行但方案不安全 | 浏览器页面不能直接写本地文件，必须经过 Electron 主进程或后端；自建写文件 HTTP 接口增加风险 | 直接复用桌面项目已有 Provider 向导 |
| Token 放在 SSD 的 `.env` | 部分可行 | OpenClaw 支持状态目录下的全局 `.env`，但现有桌面向导可能把认证信息存入 auth profile；不要强制改回纯 `.env` | 让 OpenClaw 自己保存，重点是把整个状态目录重定向到 SSD |
| 所有路径使用相对路径即可跨平台 | 不准确 | Electron 打包后 `__dirname` 可能位于 `app.asar`；相对路径基准也可能随启动方式变化 | 启动时从可执行文件位置计算 SSD 根目录，并传绝对路径 |
| 修改 `web/index.html` 可长期保留品牌栏 | 不稳定 | React/Vite 构建通常会覆盖静态产物，升级时也会丢失 | 修改源码组件或只在根目录放品牌使用说明 |
| Agent 存在 `data/openclaw.db` | 不准确 | 当前 OpenClaw 的配置、工作区、会话和运行状态分散存储，并非一个通用 `openclaw.db` | 不把该路径写入实现方案 |
| 复制数据库即可批量预置 Agent | 高风险 | 可能同时复制密钥、设备身份、会话、OAuth 状态和机器相关数据；版本升级也容易不兼容 | 改用干净工作区模板 + CLI 初始化 |
| 调用 `/api/v1/agents/import` 自动导入 JSON | 未证实 | 当前官方文档提供 `openclaw agents add/set-identity` CLI，没有确认该 HTTP 导入端点和 JSON 格式 | 删除该示例，使用官方 CLI |
| 同时支持 Windows/macOS/Linux | 理论可行但超出范围 | 三个平台需要不同运行时、启动器、签名和测试 | 当前只做 Windows x64 |
| exFAT 上运行 SQLite | 可以但需谨慎 | 异常拔盘、断电和缓存写入可能损坏状态；性能不是唯一风险 | 强制提供退出按钮和备份，不进行并发读写 |
| 预置法务、财务、健康顾问 | 技术上可做，产品风险较高 | 提示词不等于专业资格，知识可能过期，错误建议风险高 | MVP 改为文档辅助角色，并加入免责声明 |

## 3. PDF 中可以直接复用的内容

### 3.1 产品与交付规则

以下内容可以直接并入现有 PRD：

1. 不在母盘中预置任何正式 API Key。
2. 用户使用自己的 API Key，并承担模型服务费用。
3. 制作不含密钥、会话和用户资料的空白母盘。
4. SSD 根目录提供可以离线打开的使用说明。
5. 使用说明包含启动、模型配置、常见错误和技术支持入口。
6. 制作母盘前必须正常退出 OpenClaw。
7. 不允许同一块 SSD 被多台电脑同时读写。
8. 所有预置角色默认关闭不需要的危险工具权限。
9. 升级前备份配置、工作区和用户会话。
10. 母盘必须清除测试 Token、测试会话和个人文件。

### 3.2 可复用的品牌方案

按开发工作量从低到高排序：

#### A. 根目录使用说明，MVP 首选

在 SSD 根目录放置：

- `开始使用.html`
- `常见问题.html`
- `技术支持.url`
- 客服二维码图片

优点是不修改桌面应用源码，半天内可以完成，也不会被 OpenClaw 升级覆盖。

#### B. 桌面应用增加“技术支持”菜单，推荐

在现有 Electron/React 界面中增加一个固定入口，点击后打开本地帮助页或官方客服链接。只修改一个组件，不需要全局改版。

#### C. 全局品牌栏，暂缓

需要修改并维护前端布局组件，可能占用界面空间，也容易在上游升级时产生冲突。学生样品没有必要优先实现。

### 3.3 可复用的首次配置方案

直接使用 `agentkernel/openclaw-desktop` 已有配置向导：

1. 应用检测尚未配置模型 Provider。
2. 打开原项目向导。
3. 用户选择模型服务商并填写 API Key。
4. OpenClaw 保存认证信息到被重定向后的 SSD 状态目录。
5. 配置成功后进入原有聊天界面。

无需开发“前端表单 -> Gateway 写 `.env`”的新接口。

## 4. 预置 Agent 的正确实现方式

### 4.1 当前 OpenClaw 的有效概念

根据当前官方文档：

- OpenClaw 配置默认位于状态目录中的 `openclaw.json`。
- Agent 工作区与配置、认证、会话是分开的。
- 工作区可包含 `AGENTS.md`、`SOUL.md`、`IDENTITY.md`、`TOOLS.md`、`MEMORY.md` 和 `skills/`。
- 多 Agent 可通过 `openclaw agents add` 创建，通过 `openclaw agents set-identity` 设置身份。
- API Key、OAuth 信息、会话和状态不应放进可公开复制的工作区模板。

官方参考：

- [Agent 工作区说明](https://github.com/openclaw/openclaw/blob/main/docs/concepts/agent-workspace.md)
- [Agents CLI](https://github.com/openclaw/openclaw/blob/main/docs/cli/agents.md)
- [Gateway 配置](https://github.com/openclaw/openclaw/blob/main/docs/gateway/configuration.md)

### 4.2 推荐模板目录

```text
defaults/
├─ workspaces/
│  ├─ office/
│  │  ├─ AGENTS.md
│  │  ├─ SOUL.md
│  │  ├─ IDENTITY.md
│  │  ├─ TOOLS.md
│  │  └─ skills/
│  ├─ hr-docs/
│  │  ├─ AGENTS.md
│  │  ├─ SOUL.md
│  │  ├─ IDENTITY.md
│  │  └─ TOOLS.md
│  └─ business-analysis/
│     ├─ AGENTS.md
│     ├─ SOUL.md
│     ├─ IDENTITY.md
│     └─ TOOLS.md
├─ openclaw.base.json
└─ README.html
```

首次启动时把这些模板复制到：

```text
data/workspaces/<agent-id>/
```

然后用当前打包版本的 OpenClaw CLI 创建 Agent。示意命令如下，实际命令路径以打包结构为准：

```powershell
openclaw agents add office `
  --workspace "<SSD>\data\workspaces\office" `
  --non-interactive

openclaw agents set-identity `
  --agent office `
  --from-identity
```

初始化完成后写入一个版本标记，例如：

```text
data/.preset-version = 1
```

以后只有模板版本提高时才执行迁移，避免重复创建 Agent。

### 4.3 为什么不复制整个 `data` 数据库

整盘复制运行后的状态目录可能带入：

- 开发人员测试 API Key。
- OAuth Token 和 Provider 认证记录。
- Gateway 或设备身份信息。
- 旧会话和测试消息。
- 绝对路径、版本迁移状态和机器相关缓存。

这类内容肉眼不容易检查。学生项目更适合复制纯文本工作区模板，再调用官方命令生成运行状态。

## 5. MVP 建议预置的 Agent

原 PDF 提出人事、法务、财务、老板参谋和健康顾问。为了减少风险和工作量，MVP 建议只预置以下 3 个。

### 5.1 通用办公助手 `office`

**用途：** 写作、总结、会议纪要、任务拆解、工作区文件整理。

**身份文件建议：**

```markdown
# IDENTITY

- 名称：办公助手
- 定位：通用文字与信息整理助手
- 风格：简洁、结构化、先确认输出目标
```

**核心规则：**

- 默认只处理 SSD 工作区内的文件。
- 修改或删除文件前必须向用户确认。
- 不声称拥有法律、财务或医疗专业资格。
- 不确定的事实要明确标注，并建议核验来源。

**工具权限：** 文件读取、在工作区中新建文件；默认关闭系统命令、外部发送和批量删除。

### 5.2 人事文档助手 `hr-docs`

**用途：** 起草招聘 JD、面试问题、入职清单、培训计划和制度文档草稿。

**核心规则：**

- 输出是内部文档草稿，不替代劳动法律意见。
- 不根据性别、年龄、民族、健康等敏感属性作招聘决策。
- 不保存无必要的身份证、手机号等个人敏感信息。
- 涉及当地劳动法规时提示用户交由专业人员复核。

**工具权限：** 只读模板目录、读写自己的工作区；关闭命令执行和外部消息。

### 5.3 经营分析助手 `business-analysis`

**用途：** SWOT、竞品对比、成本结构、会议材料和决策备忘录。

**核心规则：**

- 明确区分事实、假设和推测。
- 给出计算过程，不伪造市场数据。
- 不直接作投资、税务或财务承诺。
- 对关键决策至少给出风险、替代方案和待验证条件。

**工具权限：** 读写自己的工作区；联网搜索仅在用户主动要求时开放。

## 6. 暂不预置的角色

### 法务 Agent

可以在二期改成“合同条款整理助手”，但必须避免“法律顾问”名称。它只能提取、对比、列风险点，最终结论交由律师确认。

### 财务 Agent

可以在二期改成“财务材料整理助手”，只做表格解释、费用分类和预算草稿，不提供报税、审计或投资建议。

### 健康顾问

不建议学生 MVP 预置。医疗建议错误的风险远高于演示价值。如果必须展示，只允许做健康信息整理，并在每次输出中提醒不能用于诊断和治疗。

## 7. Agent 文件配置建议

### 7.1 `AGENTS.md`

写执行规则、工作流程和禁止事项，例如：

```markdown
# 工作规则

1. 先确认用户要交付的文件类型和用途。
2. 只在当前 Agent 工作区内创建或修改文件。
3. 删除、覆盖或批量移动文件前必须确认。
4. 不确定的信息标注“待核实”，不得编造来源。
5. 涉及法律、财务、医疗结论时停止并提示专业复核。
```

### 7.2 `SOUL.md`

只定义沟通风格，不堆积业务流程：

```markdown
# 沟通风格

专业、耐心、简洁。先给结论，再给步骤。信息不足时先提出一个最关键的问题。
```

### 7.3 `IDENTITY.md`

只放名称、定位、图标和简短说明，不放用户资料或 API Key。

### 7.4 `TOOLS.md`

记录允许使用的工具和约束，但要注意：`TOOLS.md` 只是给 Agent 的说明，不等同于真正的权限控制。实际工具权限仍必须通过 OpenClaw 配置关闭。

### 7.5 不应预置的文件

- 不预置真实 `USER.md`。
- 不预置真实 `MEMORY.md` 和历史记忆。
- 不预置会话记录。
- 不预置认证数据库、OAuth Token 或 API Key。

## 8. 修订后的实施顺序

1. 先跑通选定的 Windows 桌面仓库。
2. 将 Electron `userData` 和 OpenClaw 状态目录重定向到 SSD。
3. 复用原项目 Provider 配置向导，不新增 Token 写入接口。
4. 制作 3 个纯文本 Agent 工作区模板。
5. 编写首次运行初始化脚本，通过官方 CLI 创建 Agent。
6. 增加根目录使用说明和技术支持入口。
7. 清除所有开发测试密钥和会话。
8. 在两台 Windows 电脑上测试首次启动、换盘符、换电脑和重置。
9. 冻结版本并制作母盘。

## 9. 对现有工作量的影响

如果只采用“帮助页 + 现有配置向导 + 3 个 Agent 模板”，可以放在原来 7-10 个有效工作日内完成：

| 新增工作 | 预计投入 |
|---|---:|
| 帮助页与技术支持入口 | 0.5 天 |
| 3 个 Agent 工作区模板 | 1-1.5 天 |
| 首次初始化和版本标记 | 1 天 |
| Agent 与换机测试 | 0.5-1 天 |

其中大部分替代原计划中的默认配置和文档工作，不应简单追加到总周期。

如果坚持开发新的 Token 页面、5-6 个专业 Agent、知识库和自动导入接口，预计额外增加 4-7 个有效工作日，并增加安全与版本维护成本，不适合当前学生 MVP。
