# 任务二：技术栈与开源项目选型

> 调研日期：2026-08-07  
> 选型原则：研发人员最轻松、最少写代码、可以在学生团队条件下完成

## 1. 选型结论

本项目不应从零开发，也不应直接修改 OpenClaw 核心代码。

推荐路线：

> Fork `agentkernel/openclaw-desktop`，把它从“安装到 Windows 本机的桌面应用”改成“放在 SSD 中运行的便携应用”；OpenClaw 本身只做版本升级和配置，不改核心逻辑。

选择它的原因：

- 已包含 Windows 10/11 x64 桌面程序。
- 已包含 Electron 界面、配置向导、OpenClaw Control UI。
- 已实现便携 Node.js 和 OpenClaw 的打包下载脚本。
- 已支持 OpenAI、Claude、DeepSeek 等模型提供方。
- 已有 Windows 安装包和发布流程，可以直接参考。
- 团队只需改路径、打包模式、默认配置和产品名称。

需要接受的条件：该项目采用 GPL-3.0。学生团队可以免费修改和销售，但分发修改版时应同时提供对应源代码、许可证和修改说明。若未来要求闭源商业化，应改为使用 MIT 许可证的官方 OpenClaw 核心，加一个自有的轻量启动器。

## 3. 为什么不选择“直接使用官方安装器”

官方 OpenClaw 支持 Windows，但官方文档仍认为 WSL2 路线更稳定；原生 Windows 可以运行 CLI 和 Gateway，但安装器、计划任务、用户目录等行为不符合“所有内容放在 SSD”这一目标。[官方安装说明](https://github.com/openclaw/openclaw/blob/main/docs/install/index.md)

因此不能简单地在 SSD 中放一个官方安装器就宣称“即插即用”。至少仍需完成：

- 将 Electron 的 `userData` 目录改到 SSD。
- 将 OpenClaw 状态目录改到 SSD。
- 将工作区、日志和备份目录改到 SSD。
- 改为便携包，不注册系统服务和计划任务。
- 启动时根据当前盘符生成绝对路径。

## 4. 推荐技术栈

### 4.1 直接继承的技术

| 层级 | 技术 | 是否需要重新开发 |
|---|---|---|
| 桌面壳 | Electron | 否，只改启动路径和品牌信息 |
| 前端 | React + TypeScript | 基本不改，复用原界面 |
| 样式 | Tailwind CSS / 原项目组件 | 不新增设计系统 |
| AI Agent 核心 | OpenClaw | 不改核心源码 |
| 运行时 | Windows x64 便携版 Node.js | 复用原项目下载和打包脚本 |
| 构建工具 | pnpm、Electron Vite、electron-builder | 复用原工程配置 |
| 模型接入 | OpenClaw 已有 Provider 配置 | 只保留 1-2 个测试过的提供方 |
| 数据保存 | SSD 本地目录 | 需要少量路径修改 |

### 4.2 建议锁定版本

- OpenClaw：开发开始时锁定一个已验证版本，不在开发期自动追最新版。
- Node.js：按该 OpenClaw 版本的 `engines` 要求选择；当前官方主分支要求 Node 22.22.3+、24.15.0+ 或相应的 25.x 版本。
- Windows：只做 Windows 10/11 x64。
- 构建机：一台 Windows 11 x64 电脑。

## 5. 只需要修改的内容

### 5.1 必改项

1. 在 Electron 启动早期，将 `userData` 指向 `<SSD>\data\desktop`。
2. 启动 OpenClaw 子进程时设置：
   - `OPENCLAW_STATE_DIR=<SSD>\data\openclaw`
   - `OPENCLAW_CONFIG_PATH=<SSD>\data\openclaw\openclaw.json`
3. 将 Agent 工作区配置为 `<SSD>\data\workspace`。
4. 改为便携版打包，生成可以直接复制的目录或单个 portable `.exe`。
5. 关闭自动更新，避免版本变化造成样品突然失效。
6. 增加“恢复出厂设置”脚本：备份后清空 `data`，再复制 `defaults`。
7. 修改应用名称、图标、欢迎文案和开源许可证页面。

### 5.2 能不改就不改

- 不重画首页。
- 不开发四张任务卡。
- 不开发独立 API Key 管理器，直接复用原项目设置向导。
- 不开发自己的聊天页。
- 不做自动启动、Windows 服务或计划任务。
- 不修改 OpenClaw Provider、Agent、工具和记忆机制。
- 不制作在线后台、数据库或账号系统。

## 6. SSD 推荐目录

```text
OpenClaw-SSD/
├─ Start.exe 或 Start.cmd
├─ app/
│  ├─ OpenClaw-SSD.exe
│  ├─ node/
│  └─ openclaw/
├─ data/
│  ├─ desktop/
│  ├─ openclaw/
│  ├─ workspace/
│  ├─ logs/
│  └─ backup/
├─ defaults/
│  ├─ openclaw.json
│  └─ workspace/
├─ Reset.cmd
├─ 使用说明.pdf
├─ LICENSES/
└─ VERSION.txt
```

所有相对路径都以启动程序所在盘符计算，不在代码中写死 `D:` 或 `E:`。

## 7. 最小技术验收

只保留以下 8 项：

1. 一台没有安装 Node.js 的 Windows 10/11 x64 电脑可以启动。
2. 不要求管理员权限。
3. 更换 SSD 盘符后仍能启动。
4. 用户可以填写一种模型 API Key 并完成对话。
5. 退出后重新打开，配置和对话仍存在。
6. 把 SSD 插到第二台电脑后仍能读取原数据。
7. 应用退出后，Gateway 进程可以正常结束。
8. “恢复出厂设置”能够清除测试用户数据并恢复默认模板。

“电脑完全不产生任何临时文件”不作为学生 MVP 的硬指标。Windows、WebView/Electron 或系统日志可能产生缓存；MVP 只承诺产品的主要配置、会话和工作区保存在 SSD。

## 8. 工作量判断

如果原仓库能够在开发机正常构建，实际编码工作主要是 3 类：

- 3-6 处路径与环境变量修改。
- 1 份 portable 打包配置。
- 1 个重置脚本和少量品牌文本。

预计技术人员 6-8 个有效工作日可以完成。最大的风险不是写代码，而是旧版桌面壳与新版 OpenClaw 的版本兼容，以及不同 Windows 电脑的权限和安全软件拦截。

## 9. 许可证与分发要求

- OpenClaw 核心为 MIT，分发时保留版权和许可证。
- `agentkernel/openclaw-desktop` 为 GPL-3.0；基于它修改和分发时，应公开相应修改版源代码，并附 GPL-3.0 文本。
- 第三方 Node、Electron 和 npm 依赖的许可证应随产品保留。
- 不预装第三方付费 API Key，不对 GPT、Claude、DeepSeek 等名称暗示官方合作。

## 10. 最终选择

**本阶段选择：基于现有项目修改。**

不直接原样使用，因为原项目数据默认写入 Windows 用户目录；不自己开发，因为桌面界面、向导、OpenClaw 运行和便携 Node 已经有人完成。学生 MVP 最合理的工作是 fork 后做小范围便携化改造。
