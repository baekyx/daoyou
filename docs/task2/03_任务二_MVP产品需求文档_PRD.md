# 任务二：预置 OpenClaw 的 SSD 移动硬盘 MVP 产品需求文档

> 版本：MVP 1.0  
> 日期：2026-08-07  
> 产品性质：学生团队技术验证样品

## 1. 产品一句话定义

一块预置 OpenClaw Windows 桌面程序和用户工作区的移动 SSD，用户插入电脑、打开程序并填写自己的模型 API Key 后，即可使用 AI 对话和基础文件处理能力。

## 2. 产品不是什么

- SSD 本身不会运行 AI，计算由连接的 Windows 电脑完成。
- SSD 中不内置 GPT、Claude 或 DeepSeek 大模型权重。
- 使用云模型 API 时，用户提示词和必要上下文会发送给模型服务商。
- MVP 不是完全离线产品。
- MVP 不承诺在所有 Windows 电脑、公司管控电脑或网吧电脑上都能运行。
- MVP 不支持 macOS。

## 3. 目标用户

首批用户应满足以下条件：

- 使用 Windows 10/11 x64 电脑。
- 能申请或已经拥有模型 API Key。
- 希望减少 OpenClaw 安装和环境配置步骤。
- 接受这是测试产品，并愿意反馈兼容性问题。

不面向完全不懂 API、要求离线大模型或企业级安全审计的用户。

## 4. 用户核心场景

### 场景 A：第一次使用

1. 用户将 SSD 插入 Windows 电脑。
2. 打开 SSD 根目录，双击 `Start.exe` 或 `Start.cmd`。
3. 程序打开现有配置向导。
4. 用户选择指定模型服务商，填写自己的 API Key。
5. 用户进入聊天页并发送第一条消息。

目标：第一次使用不需要安装 Node.js、Git、Docker 或 WSL。

### 场景 B：再次使用

1. 用户插入 SSD 并双击启动。
2. 程序直接打开原来的工作区。
3. 用户继续查看已有会话或处理 SSD 中的文件。

### 场景 C：换一台电脑

1. 用户安全退出应用并弹出 SSD。
2. 将 SSD 插入另一台符合要求的 Windows 电脑。
3. 双击启动后读取 SSD 内原有配置和工作区。

## 5. MVP 功能范围

### 5.1 必须完成

| 编号 | 功能 | 完成标准 |
|---|---|---|
| F01 | 便携启动 | 无系统 Node/Git/Docker 的电脑可打开程序 |
| F02 | 模型配置 | 至少完整支持 1 个低成本 Provider；第 2 个 Provider 为加分项 |
| F03 | 基础聊天 | 能发送消息并收到模型回复 |
| F04 | 本地工作区 | 工作区和用户文件保存在 SSD |
| F05 | 状态保存 | 应用配置、主要会话和 OpenClaw 状态保存在 SSD |
| F06 | 动态盘符 | SSD 从 D 盘变为 E 盘后仍能运行 |
| F07 | 正常退出 | 关闭应用后 OpenClaw Gateway 不残留运行 |
| F08 | 恢复出厂 | 可以备份或清除用户数据并恢复默认配置 |
| F09 | 使用说明 | SSD 根目录包含一页式使用说明和常见错误说明 |

### 5.2 可以做成“展示功能”或直接复用

- 设置页：复用开源项目原页面。
- Agent 人格：只预置一个简单的通用助手模板。
- 文件功能：仅演示读取 SSD 工作区中的 TXT、Markdown 或 PDF；不承诺复杂 Office 解析。
- 多模型：界面可以显示多个 Provider，但验收只要求团队实际测试通过 1-2 个。
- 日志查看：允许直接打开日志文件夹，不开发专门日志页面。

### 5.3 本期明确不做

- macOS 和 Windows ARM。
- 本地大模型和离线推理。
- 微信、飞书、Telegram 等消息渠道。
- 多 Agent、定时任务、企业知识库。
- 自研登录、会员、支付、云同步和后台管理。
- 自动更新和远程运维。
- 磁盘加密、密钥硬件保护和企业级安全审计。
- 自定义四张任务卡和全新视觉界面。

## 6. 数据与隐私说明

### 6.1 存在 SSD 的数据

- OpenClaw 配置和状态。
- 用户工作区文件。
- 应用主要配置。
- 会话、日志和备份中可被重定向的部分。

### 6.2 可能离开 SSD 的数据

- 调用云模型 API 时发送的提示词、上下文和用户允许发送的文件内容。
- Windows、Electron、浏览器组件或安全软件生成的系统缓存和日志。

对外文案建议使用：

> “主要工作区和应用数据随盘保存；调用云模型时，必要数据会按照所选服务商规则发送到其 API。”

不得使用“所有数据永不上云”作为卖点。

## 7. 非功能要求

| 项目 | MVP 要求 |
|---|---|
| 支持系统 | Windows 10/11 x64 |
| 权限 | 普通用户权限，尽量不触发管理员授权 |
| 启动时间 | 普通测试电脑 2 分钟以内 |
| 网络 | 需要可以访问所选模型 API |
| 容量 | 128GB 即可完成样品；建议 256GB 便于销售表达 |
| 性能 | 取决于宿主电脑和网络，不承诺模型响应时间 |
| 更新 | 样品版本固定，不自动更新 |
| 数据保护 | 提醒用户安全退出，重置前先备份 |

## 8. 验收环境

至少准备：

- 1 台 Windows 11 x64 开发机。
- 1 台未安装 Node.js、Git、Docker 的 Windows 10 或 Windows 11 测试机。
- 1 个非管理员 Windows 用户账户。
- 1 块 128GB 或 256GB 移动 SSD。
- 1 个可用测试 API Key。

## 9. 验收流程

1. 在干净测试机插入 SSD。
2. 双击启动，不执行安装程序。
3. 填写测试 API Key，完成三轮对话。
4. 退出程序，重新打开并确认配置仍在。
5. 修改盘符或换到第二台电脑，再次启动。
6. 在工作区新增文件，验证应用可读取。
7. 正常关闭并确认无明显残留进程。
8. 执行恢复出厂设置并确认用户数据已被清除。

上述 8 步全部通过，即视为 MVP 技术样品完成。

## 10. 交付物

- 1 块可演示 SSD 样品盘。
- 1 份可复制的母盘目录或镜像。
- 修改后的源代码仓库。
- 开源许可证和第三方声明。
- 一页式用户使用说明。
- 测试记录和已知问题清单。
- 3-5 分钟演示视频，可选。

## 11. 成功标准

本阶段成功不以销售数量为标准，而以“非开发成员能否在另一台 Windows 电脑独立完成首次对话”为标准。

如果用户必须打开命令行、安装依赖或修改配置文件，MVP 不通过；如果只是某些高级工具不可用，但基础启动、配置、对话和数据随盘保存正常，MVP 可以通过。
