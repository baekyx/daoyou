# 摄影师端业务与 UI 审查

## 审查范围

- 目标：摄影师凭房间号和密码直接加入现有房间，上传游客可见且持久化的照片，并直接删除本人照片。
- 页面：任务列表、加入房间、照片上传、相册、删除确认、上传质量设置。
- 视口：本地应用桌面浏览器中的 390px 移动端画布。

## 流程步骤与健康状态

1. **任务列表（修复前）— 需要改进**
   - 空状态与入口层级清楚，但“等待导游审批”的说明与最新业务规则冲突。
   - 任务卡片过去依赖受限的房间关联查询，可能显示空房间信息。
   - 证据：`01-task-list-valid.jpg`

2. **加入房间（修复前）— 需要改进**
   - 房间号输入和主按钮清晰。
   - 页面明确要求等待导游审批，制造了不必要的流程阻塞。
   - 证据：`02-join-before-valid.jpg`

3. **上传页面（修复前）— 不可用**
   - `Images` 图标未导入，页面进入后触发错误边界，无法选择或上传照片。
   - 证据：`03-upload-error-before-valid.jpg`

4. **上传页面空状态（修复后）— 健康**
   - 未选择房间时不再白屏，明确提示从任务列表进入。
   - 上传按钮保持禁用，避免错误操作。
   - 证据：`04-upload-after-valid.jpg`

5. **密码直入页面（修复后）— 健康**
   - 文案改为“密码验证后直接加入”，并说明加入状态会保存。
   - 仍保留六位房间号的单一主任务，认知负担低。
   - 证据：`05-join-after-valid.jpg`

6. **摄影师相册（修复后）— 健康**
   - 照片按房间持久化展示。
   - 删除入口不再依赖鼠标悬停，触屏设备也能发现和操作。
   - 证据：`06-album-after-valid.jpg`

7. **删除确认（修复后）— 健康**
   - 不再要求填写删除原因或等待导游处理。
   - 清楚说明删除后游客不可见且不可撤销，危险操作使用红色主按钮。
   - 证据：`07-delete-confirm-after-valid.jpg`

## 已处理的问题

- 摄影师加入流程从“申请并等待审批”改为“密码验证后直接加入”。
- 新增数据库 RPC 迁移，成功后将摄影师房间成员状态持久化为 `approved`。
- 上传页新增原图、高清、标准三档，高清与标准在浏览器本地压缩后上传。
- 上传状态区分图片处理与网络上传，并显示处理后的文件大小。
- 修复上传页 `Images is not defined` 白屏。
- 摄影师可直接删除本人照片，游客端随数据库记录删除立即不可见。
- 相册房间信息改用安全接口读取，避免权限策略导致名称为空。
- 删除按钮增加键盘焦点样式和 44px 触控区域。

## 证据限制

- 未执行“确认删除”，避免删除现有业务照片。
- 新增的密码直入 RPC 仅保存在本地迁移文件中；在遵守“只能本地修改”的前提下，没有推送到远端 Supabase。因此完整的密码验证成功与真实上传链路，需要数据库迁移获得单独授权后才能实测。
- 截图可确认视觉层级和可见状态，不能单独证明完整的屏幕阅读器兼容性。
