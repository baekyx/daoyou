## 系统性结论

1. 主问题不是单个卡片，而是底栏与正文共用滚动层，短屏和长列表出现可见遮挡。
2. 任务页、流程页、设置页分别形成了三套字号和间距，缺少统一阅读节奏。
3. 390px 基本可用，但 320px 不能只缩小字号，需要重排、压缩装饰并保留 44px 触控尺寸。
4. 加入、上传和隐私页的大面积留白有两类：自然任务结束后的留白可保留；内容被固定高度或底栏截断造成的留白必须修复。
5. 弹层、长协议、长列表和反馈表单均需要独立滚动边界，不能依赖页面整体滚动。
6. 加载、空、错误必须是三种独立语义；任务接口错误不能继续复用空状态。

## 统一方向

- 页面骨架：正文唯一滚动，底栏独立占位，页头在长页内吸顶。
- 字体：30px 页标题、20px 区块标题、16px 卡片标题、14px 正文、12px 辅助信息。
- 间距：20px 页面边距，16px 区块间距，12px 卡片内部关系，最小触控高度 44px。
- 状态：进行中、完成、空、错误、禁用只改变语义和色彩，不改变卡片骨架。
- 窄屏：缩短 Hero 和上传区域，卡片重排；不缩小到不可读字号。

## 第一批实施结果

- 任务、相册、我的三个主 Tab 已改为“正文单独滚动 + 底栏独立占位”，末项不再被底栏盖住。
- 进行中与已完成任务沿用同一卡片骨架，仅状态色和行动文案变化，切换不再发生结构跳变。
- 任务加载态补充可识别骨架；任务接口异常改为明确错误态和“重新加载”，不再伪装为空状态。
- 390px 与 320px 分别调整 Hero、高度、卡片重排和内边距，同时保留不小于 44px 的触控尺寸。
- 加入、重新验证、上传、删除、个人设置、存储、隐私、帮助与身份账号统一到同一字号、间距和浅绿层级体系。
- 路由、跳转、按钮操作及数据接口保持原链路；仅修复已结束任务进入字幕/纪要的既有异常跳转。
